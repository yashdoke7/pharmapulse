# `contracts/` — the frozen interfaces

**Owner:** the **lead**. Nobody else merges a change here without an announcement and a change-log line.

---

## Target

> Make four pods able to work in parallel from hour one, by agreeing the shapes before anyone writes
> the code that produces them.

With 8 people and 4 days, integration is not a phase you do at the end — it is a property you either
maintain from the start or lose entirely.

## Contents

| Path | What | Producer → Consumer |
|---|---|---|
| `schemas/gold.sql` | contract **C1** — the gold and feature tables | Pod A → Pod B |
| `schemas/forecast.sql` | contract **C2** — the forecast store, members, demand class | Pod B → Pod C |
| `fixtures/*.json` | contract **C5** — nine shape-correct mock API responses | Pod A/C → Pod D |
| `openapi.json` | contract **C3** — generated by `scripts/dump_openapi.py` | Pod C → Pod D |

The full narrative of all five contracts, including every JSON shape, is in **`CONTRACTS.md` at the
repo root.** That file is the authority; these are its machine-readable halves.

## Inputs / Outputs

**Inputs:** human agreement, recorded once.
**Outputs:** four pods that never block each other.

## The fixtures

```
series.json  history.json  forecast.json  recommend.json  risk.json
explain.json  metrics.json  settings.json  health.json
```

Every one carries the full `{data, meta}` envelope. Regenerate with:

```bash
python scripts/make_fixtures.py
```

- **Pod D** builds every screen against these before the API exists (`VITE_USE_FIXTURES=1`).
- **Pod C** serves them verbatim on Day 1 (`PHARMAPULSE_FIXTURES=1`), then swaps in real reads one
  endpoint at a time — and keeps the switch working all week as the stage fallback.
- **`tests/contract/test_matches_fixtures.py`** asserts live responses match these keys and types, so
  a shape change goes red in CI before it breaks Pod D's build.

## How to change a contract

A contract change is **its own PR**, containing only:

1. the `CONTRACTS.md` edit,
2. a line in its change-log table,
3. the regenerated fixture,

announced in the team channel **before** it is merged. Then, and only then, the code changes.

**After Day 2, a contract change needs the lead's approval.** By that point three pods are building
on it and a silent shape change costs more than the feature it enables.
